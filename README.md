# AI creator portfolio

Одностраничный сайт-портфолио: монтаж коротких вертикальных видео (Instagram Reels, TikTok)
и видео, собранное через ИИ.

Страница одна: hero → About → Work → контакты. Работы лежат ниже на той же странице,
переключаются кнопками **All / AI-generated / Editing**, по клику на карточку открывается
окно с плеером и описанием.

Чистая статика: ни сборки, ни фреймворков, ни серверного кода. HTML, немного CSS и ванильный JS.

## Что где лежит

```
public/index.html   вся страница: разметка, стили и скрипт
public/works.js     список работ — отсюда страница берёт карточки, фильтры и плеер
public/media/       портрет, постеры (webp) и видео (mp4)
.github/workflows/  публикация на GitHub Pages
```

Дизайн-токены (цвета, шрифты) заданы в `:root` внутри страницы — страница ни от чего не зависит,
кроме Google Fonts.

## Как добавить работу

Всё в одном файле — `public/works.js`.

1. Пережми ролик под веб и положи в `public/media/video/<slug>.mp4`:

   ```bash
   ffmpeg -i in.mp4 -vf "scale='min(iw,if(gt(iw,ih),1920,1080))':-2" \
     -c:v libx264 -crf 23 -preset faster -pix_fmt yuv420p \
     -c:a aac -b:a 128k -movflags +faststart out.mp4
   ```

   Строка `scale` сама решает: вертикальное сводит к 1080 по ширине, горизонтальное — к 1920,
   и никогда не растягивает мелкое. `+faststart` обязателен, иначе плеер ждёт загрузки всего
   файла. Если ролик выходит тяжелее ~10 МБ — подними `-crf` до 27–29.

2. Сними кадр-превью (примерно с трети ролика, чтобы не поймать чёрный кадр):

   ```bash
   ffmpeg -ss 5 -i in.mp4 -frames:v 1 -vf "scale='min(iw,720)':-2" \
     -c:v libwebp -quality 80 public/media/posters/<slug>.webp
   ```

3. Скопируй соседний объект в `works.js` и смени поля:

   | поле | что это |
   |---|---|
   | `slug` | короткое имя латиницей, совпадает с именем файлов |
   | `num` | номер карточки, `"01"`, `"02"`, … |
   | `kind` | `"ai"` — сделано через ИИ, `"edit"` — чистый монтаж; по нему работают кнопки |
   | `ratio` | `"9/16"` вертикальное, `"16/9"` горизонтальное |
   | `name` / `sub` | заголовок и подпись в карточке |
   | `brief` | задача одним абзацем |
   | `did` | что именно сделано, списком |
   | `tags` | чипы под карточкой |
   | `file` / `poster` | пути к видео и превью |
   | `embed` | вместо `file`, если видео лежит на YouTube или Vimeo |

Порядок карточек на странице = порядок в массиве. Если `file` и `poster` оставить пустыми,
карточка покажет заглушку `video soon` — страница не ломается.

## Запуск и публикация

Локально хватит любого статического сервера из папки `public`:

```bash
python -m http.server 8000 --directory public
```

В репозитории лежит и конфиг Cloudflare Workers (`wrangler.jsonc`), если сайт понадобится
выложить туда:

```bash
npm install
npm run dev
```

На **GitHub Pages** сайт публикуется сам: при пуше в `main` workflow
`.github/workflows/pages.yml` отдаёт содержимое `public/`.

Все ссылки внутри страницы относительные — поэтому сайт одинаково работает и в корне домена,
и по адресу вида `user.github.io/имя-репозитория/`.
